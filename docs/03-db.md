## 1. MariaDB 설치 및 서비스 활성화

📍 **DBServer**
```bash
# MariaDB 패키지 설치
dnf install -y mariadb-server

# 한글 및 이모지 지원을 위한 커스텀 설정 파일
cat > /etc/my.cnf.d/custom.cnf <<'EOF'
[mysqld]
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
EOF

# 서비스 기동 및 부팅 시 자동 시작 설정
systemctl enable --now mariadb

# 상태 확인 (utf8mb4 가 나오면 정상)
mariadb -e "SHOW VARIABLES LIKE 'character_set_server';"

# MariaDB 초기 보안 마법사 실행
mariadb-secure-installation
```

- `utf8mb4` = 4바이트 UTF-8. 한글과 이모지까지 모두 저장 가능 (MySQL 의 `utf8` 은 3바이트라 이모지 불가).
- `/etc/my.cnf.d/*.cnf` 는 MariaDB 가 시작할 때 자동으로 읽는 설정 폴더.

## 2. 초기 보안 마법사 답변

| 질문 | 대답 | 이유 |
|---|---|---|
| Enter current password for root | Enter | 설치 직후엔 비밀번호 없음 |
| Switch to unix_socket authentication | Y | 서버의 OS root 만 비밀번호 없이 DB root 로 접속 |
| Change the root password | N | unix_socket 인증을 쓰므로 불필요 |
| Remove anonymous users | Y | 아무나 접속하는 익명 계정 제거 |
| Disallow root login remotely | Y | 원격 root 접속 차단 |
| Remove test database | Y | 누구나 쓰는 test DB 제거 |
| Reload privilege tables | Y | 바뀐 권한 즉시 반영 |

## 3. 사내 시스템 DB & 스키마 구축

📍 **DBServer**
```bash
# MariaDB 접속 (아래 SQL 은 접속한 상태에서 실행)
mariadb
```

### DB 와 테이블 생성

```sql
CREATE DATABASE filehub DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE filehub;

CREATE TABLE users (
  id            INT NOT NULL AUTO_INCREMENT,
  username      VARCHAR(50)  NOT NULL,
  email         VARCHAR(255) NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  name          VARCHAR(50)  NOT NULL,
  role          ENUM('admin','staff') NOT NULL DEFAULT 'staff',
  team          VARCHAR(20) DEFAULT NULL,
  failed_count  INT NOT NULL DEFAULT 0,
  is_locked     TINYINT(1) NOT NULL DEFAULT 0,
  last_login_at DATETIME DEFAULT NULL,
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uq_users_username (username),
  UNIQUE KEY uq_users_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;

CREATE TABLE folders (
  id         INT UNSIGNED NOT NULL AUTO_INCREMENT,
  name       VARCHAR(100) NOT NULL,
  parent_id  INT UNSIGNED DEFAULT NULL,  -- NULL = 맨 위 팀 폴더
  dept       VARCHAR(20)  DEFAULT NULL,  -- 팀 키 (general, team1 ...)
  created_by INT DEFAULT NULL,           -- users.id, FK 없음 (사용자 삭제돼도 폴더 유지)
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  quota_mb   INT DEFAULT NULL COMMENT '폴더 용량 한도(MB), NULL이면 제한 없음',
  PRIMARY KEY (id),
  KEY idx_folders_parent (parent_id),
  CONSTRAINT fk_folders_parent FOREIGN KEY (parent_id) REFERENCES folders (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;

CREATE TABLE files (
  id            INT NOT NULL AUTO_INCREMENT,
  original_name VARCHAR(255) NOT NULL,
  stored_name   VARCHAR(64)  NOT NULL,
  storage       VARCHAR(10)  NOT NULL DEFAULT 'nfs',
  dept          VARCHAR(20)  DEFAULT NULL,
  size_bytes    BIGINT NOT NULL DEFAULT 0,
  uploaded_by   INT NOT NULL,
  folder_id     INT UNSIGNED DEFAULT NULL,
  is_deleted    TINYINT(1) NOT NULL DEFAULT 0,  -- 소프트 삭제
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_files_folder (folder_id),
  KEY idx_files_uploader (uploaded_by),
  CONSTRAINT fk_files_user FOREIGN KEY (uploaded_by) REFERENCES users (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

| 테이블 | 칸 | 쓰임 |
|---|---|---|
| `users` | `password_hash` | werkzeug 해시 (평문 저장 안 함) |
| | `team` | 소속 팀 키 — 다른 팀 폴더 접근 차단 기준 |
| | `failed_count` / `is_locked` | 연속 로그인 실패 횟수 / 잠금 여부 (5회 → 잠금, 가입 승인 대기도 잠금 상태) |
| `folders` | `parent_id` | NULL 이면 맨 위 팀 폴더, 값이 있으면 하위 폴더 (자기 참조 FK) |
| | `dept` | 팀 키. **파일서버 `/nfs/share/uploads/<dept>` 폴더 이름과 같아야 함** |
| | `quota_mb` | 폴더 용량 한도. 하위 폴더는 가장 가까운 상위 폴더의 한도를 따름 |
| `files` | `stored_name` | 디스크 저장 이름 `팀/UUID` (한글·특수문자·중복 회피) |
| | `original_name` | 사용자에게 보여 줄 원래 파일 이름 |
| | `is_deleted` | 소프트 삭제 — 행은 남기고 표시만 |
| | `updated_at` | 행이 바뀌면 자동 갱신 (`ON UPDATE CURRENT_TIMESTAMP`) |

### 맨 위 팀 폴더와 용량 한도

```sql
INSERT INTO folders (name, parent_id, dept, quota_mb) VALUES
  ('공용', NULL, 'general', 2048),
  ('1팀',  NULL, 'team1',   500),
  ('2팀',  NULL, 'team2',   500),
  ('4팀',  NULL, 'team4',   500),
  ('5팀',  NULL, 'team5',   500),
  ('6팀',  NULL, 'team6',   500);

-- 맨 위 폴더 확인
SELECT id, name, dept, quota_mb FROM folders WHERE parent_id IS NULL;
```
> `quota_mb` 는 파일서버 XFS 프로젝트 쿼터([01. NFS 1-7)](01-nfs.md#7-팀-폴더-용량-한도-xfs-프로젝트-쿼터))와 같은 값으로 맞춘다.

### DB 계정과 권한 (용도별 분리 · 최소 권한)

```sql
-- 웹 앱: filehub DB 전체 읽기/쓰기 (폴더 삭제에 DELETE 필요)
CREATE USER 'filehub_app'@'192.168.56.101' IDENTIFIED BY '<앱 비밀번호>';
GRANT SELECT, INSERT, UPDATE, DELETE ON filehub.* TO 'filehub_app'@'192.168.56.101';

-- 관제(Grafana): 조회만, users 는 password_hash 제외
CREATE USER 'filehub_grafana'@'192.168.56.104' IDENTIFIED BY '<관제 비밀번호>';
GRANT SELECT ON filehub.files   TO 'filehub_grafana'@'192.168.56.104';
GRANT SELECT ON filehub.folders TO 'filehub_grafana'@'192.168.56.104';
GRANT SELECT (id, username, email, name, role, team, failed_count, is_locked, last_login_at, created_at)
  ON filehub.users TO 'filehub_grafana'@'192.168.56.104';
-- (filehub_grafana 는 Grafana MySQL 데이터소스에서 사용 : 05. 관제서버 6)-B)

-- mysqld_exporter: 로컬에서 상태 지표만
CREATE USER 'exporter'@'localhost' IDENTIFIED BY '<exporter 비밀번호>' WITH MAX_USER_CONNECTIONS 3;
GRANT SELECT, PROCESS, BINLOG MONITOR, SLAVE MONITOR ON *.* TO 'exporter'@'localhost';
GRANT SELECT ON performance_schema.* TO 'exporter'@'localhost';
-- (exporter 는 아직 관제에 연결하지 않음. 연결하려면 DB Alloy 에 prometheus.exporter.mysql 블록 추가)
```

| 계정 | 접속 위치 | 권한 | 용도 |
|---|---|---|---|
| `filehub_app` | 56.101 (웹서버) | filehub 전체 CRUD | Flask 앱 |
| `filehub_grafana` | 56.104 (관제) | files · folders 조회, users 는 **칸 단위** 조회 | Grafana 대시보드 |
| `exporter` | localhost | 상태 지표 조회, 동시 접속 3 | (예비) mysqld_exporter |

- `'계정'@'호스트'` — MariaDB 는 **같은 이름이라도 접속 IP 가 다르면 다른 계정**이다. IP 를 고정하면 다른 서버에서는 그 계정으로 접속할 수 없다.
- `GRANT SELECT (칸, 칸, ...)` = 칸 단위 권한. 관제 계정이 `password_hash` 를 볼 수 없게 한다.

```bash
# 📍 DBServer — 사용자 계정 및 허용된 IP 등록 확인
mariadb -e "SELECT user, host FROM mysql.user;"
```
> 목록에 `root | %` 가 있으면 원격 root 가 열린 상태 (보안 마법사의 Disallow root login remotely 와 어긋남)

```bash
# 원격 root 계정 지우기 (root@localhost 는 unix_socket 으로 그대로 사용)
mariadb -e "DROP USER IF EXISTS 'root'@'%';"
```
> 팀원이 원격 root 로 접속해 쓰고 있지 않은지 먼저 확인할 것

## 4. 방화벽 (3306 은 웹서버 · 관제서버만)

웹 앱(`filehub_app@192.168.56.101`)과 Grafana(`filehub_grafana@192.168.56.104`)만 DB 에 접속하게 연다.

📍 **DBServer**
```bash
# 웹서버에서 오는 3306 허용
firewall-cmd --permanent --zone=work --add-rich-rule='rule family="ipv4" source address="192.168.56.101" service name="mysql" accept'

# 관제서버(Grafana)에서 오는 3306 허용
firewall-cmd --permanent --zone=work --add-rich-rule='rule family="ipv4" source address="192.168.56.104" service name="mysql" accept'

# 방화벽 다시 읽기
firewall-cmd --reload

# 규칙 확인 (mysql 두 줄이 보이면 정상)
firewall-cmd --zone=work --list-rich-rules
```

> 접속 확인은 [04. 웹/WAS 1-3)](04-web.md#3-db-접속-확인-웹서버에서) 의 `mysql -h 192.168.56.103` 명령으로 한다.
